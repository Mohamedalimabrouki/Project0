# How this film is made (code only)

Every picture of *02 · Aliasing* is drawn by a program, 30 times per second, from the equations. There is no Blender file and nothing is animated by eye. This folder holds that program.

**Why code for this piece?** A video is itself a sampling machine: it shows 30 still pictures every second. When the program draws a wheel turning at exactly 5.5 turns per second, your screen really shows it creeping backwards. Drawing each frame from the exact physics is the only honest way to demonstrate aliasing.

## What is in here

| Path | What it is |
|---|---|
| `engine/ep.js` | The drawing library: house colours, text in English, French and Arabic, equations, arrows, the wheel, the car, the series mark. |
| `engine/stage.js`, `engine/stage.html` | The "stage": a web page that loads the scenes and draws any frame on request. |
| `scenes/` | One file per scene. Each one draws its frame from the time `t` only. |
| `data/comps.json` | The timeline: which scenes, in which order, how long. Also the Short (9:16), the hero still and the thumbnail. |
| `data/strings/` | Every word on screen, in English, French and Arabic. |
| `data/voice/` | The few on-screen lines reworded for the narrated Short (used only with `--voice`). |
| `audio/` | Music and sound effects, also generated by code. `audio/voice.py` turns a recorded narration into the narrated versions. |
| `tools/` | Contact sheets (many frames on one image) and the subtitle maker. |
| `qa/` | Automatic checks: flashing (photosensitivity) and "is this wheel really frozen". |
| `render.mjs` | Draws frames with a hidden Chrome browser and saves them as PNG images. |
| `make_film.sh` | Builds every final file in one go. |
| `web/` | The screening-room web page (`page.html`) and `make_page.sh`, which packages the finals for it. |
| `SCENE_GUIDE.md` | The rules for anyone writing a scene. |

## Build the finals on your computer

You need, once:

1. **Node.js** (version 18 or newer) from nodejs.org.
2. **Python 3** and these packages: `pip install numpy scipy soundfile pyloudnorm pillow`
3. **ffmpeg** (on a Mac: `brew install ffmpeg`).
4. In this folder, in a terminal: `npm install` then `npx playwright install chromium` (this downloads the hidden browser).

Then, still in this folder:

```bash
./make_film.sh          # everything: 3 languages, the Short, stills, subtitles (about 30 to 60 minutes)
./make_film.sh en       # only the English versions
```

The results land in `../video/`, `../subtitles/` and `../renders/`.

## Look at one moment without building everything

```bash
node render.mjs --scene s04_trick --at 12            # one frame, saved in build/.../frames/
node render.mjs --scene s04_trick --every 15 --contact   # a contact sheet of the scene
node render.mjs --scene s05_rule --lang ar --at 20   # the Arabic version
```

## The narrated version

The narration is recorded by a person (see [`../voice/README.md`](../voice/README.md) and the script [`../voice/SCRIPT.md`](../voice/SCRIPT.md)). Then:

```bash
python3 audio/voice.py build --lang en --take ~/en.m4a    # one language, from one recording
python3 audio/voice.py build                              # every recording found in ../voice/raw/
python3 audio/voice.py script                             # rewrite ../voice/SCRIPT.md after changing ../voice/script.json
```

What `build` does, in plain words:

1. **Cleans** the recording: removes rumble, lowers steady hiss by at most 10 dB (learnt from the quiet moments), shapes the tone (a little less boxiness, a little more presence and air), softens loud "s" sounds, and evens out the level with a gentle compressor.
2. **Finds the lines.** It splits the recording at the pauses and matches the parts to the 34 lines by their length and their sound. A slip, a cough or a line said twice is left out; when a line is said twice, the last take wins. The report says which second of the recording became which line.
3. **Places each line on its moment** (the caption time of that line in the film and in the Short). A line that is too long starts up to 0.45 s early, and only if that is not enough is it sped up, by 10 % at most (rubberband, pitch unchanged).
4. **Mixes.** The music goes down 7 dB for the whole narrated film and a further 11 dB while the voice speaks, with an extra 5 dB dip in the 0.7 to 4.5 kHz band where speech lives. The dip holds through short pauses between lines, so the music never pumps; it rises in the longer breaths of the film. Engines, rotors and motors step back 8 dB under the voice. On the stand-in tests the voice sat 12 to 14 dB above everything else.
5. **Masters** to -14 LUFS with true peaks under -1.5 dBTP, like the music-only versions.
6. **Subtitles** from the real voice times (`../subtitles/02-aliasing_narrated_<lang>.srt` and `_9x16_narrated_`), long lines split in two.
7. **Pictures:** the film is rendered without the caption band (`render.mjs --no-captions`), because the voice says those words and burned-in captions under a narrator look amateur; the Short keeps its captions (`--voice` swaps in the reworded lines of `data/voice/short.json`). Missing pictures are rendered on the way.

Outputs: `../video/02-aliasing_16x9_<lang>_narrated.mp4` and `../video/02-aliasing_9x16_<lang>_narrated.mp4`; mixes, the voice alone and the report in `build/audio/voice/`. The music-only versions are never touched. `--out <folder>` sends everything to another folder, for trying things out.

## The web page

`web/page.html` is the private screening room (the film in three versions, chapters, subtitles, both layers, the Short). `./web/make_page.sh` cuts the finals into 4-second pieces for streaming and writes `build/web/`, ready to publish as a claude.ai artifact.

## Change a word

Edit the text in `data/strings/<scene>.json` (each line has `en`, `fr` and `ar`), then build again. Everything else follows: layout, subtitles, all three videos.
